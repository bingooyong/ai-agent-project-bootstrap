# 产品需求文档

版本：V0.2；日期：2026-11-20；状态：待评审设计基线。

## 1. 产品目标

产品品牌为 **Oh My Blueprint（OMBP）**，目标仓库为 `oh-my-blueprint`，CLI 为 `ombp`，使用 `.ombp/` 项目配置、`OMBP_` 环境变量与 `ombp-` 自有包前缀。Go Module 目标为 `github.com/bingooyong/oh-my-blueprint`。当前没有 Go Module 或二进制实现，分发与仓库命名空间状态以[命名规范](08-Naming.md)为准。

让 AI Agent 在新建或已有工程中，根据实际文件理解项目，建立适用的工程规则，配置所需工作流，并在项目变化后持续发现规则漂移。

产品形态为本地 CLI。规则定义与 Agent 输出分开管理，确定性扫描与可选 AI 分析分开处理。首期不依赖模型、数据库或常驻服务。

“任何新工程”是长期覆盖目标。MVP 只承诺已实现并通过样本验证的技术栈；对空目录、不支持的语言或证据不足的工程，输出未知项及适用的通用规则，不猜测业务架构。

## 2. 用户与场景

| 用户 | 触发场景 | 期望结果 |
| --- | --- | --- |
| 独立开发者 | 新建 Go、Python 或 React 工程 | 预览事实、规则和文件差异，明确应用后得到可用的 Codex 指令 |
| 存量项目维护者 | 已有手写 AGENTS.md | 发现已有内容，保留原文件，先输出接管或合并建议 |
| 多模块工程维护者 | 后端与前端规则不同 | 按实际模块生成必要的目录级规则，避免无差别创建目录 |
| 团队规范负责人 | 多仓库基线版本不一致 | 在后续治理阶段锁定规则版本并输出可追溯检查结果 |
| CI 维护者 | 构建脚本从 npm 迁到 pnpm | 静态识别命令来源变化并报告漂移，不能声称运行成功 |
| 多 Agent 使用者 | 同时使用 Codex、Claude Code、Cursor | 后续由统一规则源生成各自配置，报告无法表达的能力 |

主流程为 `Scan → Profile → Resolve → Plan/Diff → Apply → Check`。现有项目默认停在预览结果；用户通过明确的应用指令授权写入当前计划所列的本地文件。

## 3. 功能需求

| --- | --- | --- |
| FR-001 | 静态扫描语言、框架、构建和测试工具、数据库线索、CI、模块及已有 Agent 配置；每项输出来源路径、定位信息、置信度、未知状态 | MVP |
| FR-002 | 输出带 Schema 版本的项目画像；扫描事实、人工确认值及其冲突分别保留；支持画像差异比较 | MVP；自动增量比较在 Phase 2 |
| FR-003 | 从内置基线和项目自定义规则中匹配规则，检查依赖、显式冲突及结构化约束；输出选择原因和无法判断项 | MVP |
| FR-004 | 生成 Codex 根规则和有证据支持的目录规则；核心命令靠前，长期规则简洁，详细内容可导航；未知命令不得补造 | MVP |
| FR-005 | 默认预览；支持 Dry Run、Diff、计划绑定及受管文件校验；已有未接管文件、人工修改和过期计划阻断写入 | MVP |
| FR-006 | 锁定工具、规则、模板、适配器版本和内容摘要；同输入可重现；版本变化不得静默重新解析 | MVP |
| FR-007 | `check` 检查缺失文件、Schema、引用路径、受管哈希、静态命令来源、必需规则及冲突；提供 JSON 和确定的退出码 | MVP |
| FR-008 | `update` 重新扫描并生成更新计划；`audit` 扩展漂移、冗余和跨文件语义线索；区分确定性发现与人工审查项 | Phase 2 |

### 3.1 MVP 识别范围

首批以 Go、Python、TypeScript/JavaScript、React 为语言/框架样本；识别 MySQL、PostgreSQL 的声明式依赖线索，并匹配基础数据库安全规则。Oracle 首期提供基础规则，自动识别覆盖取决于明确依赖样本；不得把通用 SQL 文件视为 Oracle 的确认依据。

Go module、Python 项目清单、package.json、锁文件、现有 CI/构建配置是主要证据。React 依赖出现只证明声明使用，不能证明前端已运行。Java、Rust、Next.js、Django 等属于扩展探测器候选，不纳入 MVP 必达识别指标。

Monorepo 首期按显式工作区/模块清单建立模块画像，不能仅按 `backend`、`frontend` 名称判断；未知嵌套结构保留为候选模块。数据库访问、网络连通性、实际框架运行状态均不由静态扫描确认。

### 3.2 十五项工程治理基线

| 领域 | 输出规则应明确的行为 | 验证边界 |
| --- | --- | --- |
| 需求与范围 | 理解现有行为，区分明确需求、必要修改与自主优化；不擅自删功能或扩大重构 | 范围说明可静态检查，业务正确性需评审 |
| 修改前调查 | 阅读模块、接口、数据、测试和文档；检查 Git 状态并保护未提交工作 | 检查记录和差异为证据 |
| 架构一致性 | 复用现有分层和组件，避免循环依赖与重复实现，不擅换核心基础设施 | 依赖图、代码审查、架构测试 |
| 代码质量 | 异常可观察，不吞错、不假实现，不关闭类型/断言制造通过 | 测试和代码审查 |
| 数据库 | 迁移兼容、恢复、幂等、索引、事务、锁和并发一致性；生产操作须有范围授权 | 不能由 AGENTS.md 提供数据库权限隔离 |
| 接口兼容 | 识别调用方，保护字段语义、事件、消息和缓存契约，验证鉴权和错误路径 | 契约与集成测试 |
| 安全 | 凭证脱敏、服务端鉴权、输入和上传校验，审查注入/越权/SSRF 等适用威胁 | 安全测试与硬权限控制 |
| 测试证据 | 新功能/缺陷/权限/边界需对应测试；失败和未执行如实报告 | 静态、Mock、集成、UAT 证据分别标注 |
| Git | 保护用户修改；提交、推送、合并、标签、发布和历史改写按明确授权执行 | 会话已有授权可复用，不反复索要同一授权 |
| 环境与发布 | 明确 DEV/TEST/UAT/PROD，默认本地/授权测试环境，发布有验证和恢复方案 | 工具权限、CI 和平台审批约束实际执行 |
| 前端 | 复用设计系统，覆盖加载、空、错、权限、表单、重复提交等状态 | 交互、可访问性与 E2E 验证 |
| 文档一致 | 同步适用的需求、设计、API、数据库、配置、部署、测试与变更说明 | 引用和内容差异审查 |
| 依赖治理 | 先复用，审查许可证、维护状态、已知漏洞和锁定版本 | 离线报告必须注明漏洞库时效性 |
| 对抗式审查 | 从错误路径、权限、并发、数据丢失和假实现检查，发现须有位置、影响和建议 | 不把开发者自述视为证据 |
| 最终交付 | 报告完成、文件、方案、命令、结果、未完、风险和人工事项 | 无运行证据不得写运行 PASS |

以上是规则内容需求，不意味着工具能静态证明所有领域合规。需求追溯、复杂任务 SDD、阶段验收、多环境隔离、制品版本和文档知识地图纳入通用规则；一次性会话要求不自动固化。

## 4. 非功能需求

| 编号 | 约束 | 验证方式 |
| --- | --- | --- |
| NFR-001 | 本地优先、离线可用；默认不联网、不调用模型、不执行项目脚本、不安装 Skill | 无网络/恶意脚本夹具，监测外部调用 |
| NFR-002 | 不读取凭证、`.env` 内容及证书/私钥；忽略 VCS、依赖和产物；不跟随越界链接 | 文件访问与符号链接攻击夹具 |
| NFR-003 | 产品受管文件写入限制于目标根内已计划的文件；报告输出限于根内显式指定路径；仅预览的 `--plan-out` 可写用户明确指定的根外计划文件，仍拒绝覆盖、符号链接和敏感路径；保留自定义内容、失败可恢复 | 中断、并发修改、根外输出约束、回滚与重跑测试 |
| NFR-004 | 排序、编码、换行、版本和哈希规则固定；时间不影响生成正文；相同锁与输入生成相同字节 | Golden 和跨平台摘要比较 |
| NFR-005 | macOS/Linux/Windows，amd64/arm64 目标；原生平台验证与交叉编译分开记载 | 平台矩阵；未运行的平台标 NOT_RUN |
| NFR-006 | 大仓库有文件数、大小、深度和总读取量限制；触限不得静默出完整结论 | 上限边界夹具；性能目标在 WP-02 实测定标 |
| NFR-007 | 规则版本、来源、选择路径和输出均可追溯；错误输出不泄漏敏感信息 | Schema、报告、脱敏检查 |
| NFR-008 | AGENTS.md 指令预算由适配器配置；无法容纳完整有效规则时阻断或要求显式精简，不静默截断 | 层级累计大小与不可丢弃规则测试 |

不承诺对任意自然语言矛盾作完备判断，不以低误报宣传代替基准数据。识别精度和资源指标在样本集固定后报告分母、误报、漏报及测量条件。

## 5. MVP 验收条件

| 编号 | 必须满足的结果 | 关联需求 |
| --- | --- | --- |
| AC-01 | 受支持样本与空/未知项目均有画像；每个推断有证据，不生成虚构命令 | FR-001/002 |
| AC-02 | 离线完成规则解析、Codex 根与必要目录规则预览，不创建无关模块 | FR-003/004 |
| AC-03 | 默认和 Dry Run 不改项目；显式计划应用只写列出的本地文件 | FR-005 |
| AC-04 | 未接管/人工修改/标记损坏/计划过期/符号链接等情形阻断并保护原文 | FR-005，NFR-002/003 |
| AC-05 | 同输入、同锁生成字节一致；哈希或版本漂移可检测；未知 Schema 拒绝应用 | FR-006 |
| AC-06 | 必需规则缺失、结构化冲突、缺失路径和命令来源变化产生可定位报告及正确退出码 | FR-007 |
| AC-07 | 自定义规则保留，P0 不可被下层直接削弱，依赖环阻断，语义未知单独报告 | FR-003 |
| AC-08 | 恶意脚本、凭证、越界路径、并发修改和中断恢复测试有实际执行证据 | NFR-001/002/003 |
| AC-09 | 平台矩阵、命令说明及需求到测试映射齐全；未运行部分明确列出 | FR-013，NFR-005 |
| AC-10 | Skills、多 Agent、AI、企业治理不混入 MVP 完成声明 | FR-009～012 |

## 6. 非目标与待决策

本轮仅创建文档；产品首期不建设 Web/SaaS、IDE、数据库、完整 MCP 管理平台，不修改业务代码，不操作生产，不代替 CI 和分支保护。CLI 不自动 commit/push/merge，也不写用户全局配置。

实施前待定：Go 最低版本与依赖版本、YAML/Schema 实现库、内置规则逐条正文、受支持工具版本窗口、性能预算、企业例外签发机制。方案见架构决策；未定项不能伪装为已完成调研。
